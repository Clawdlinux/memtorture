## T2: core types, worker protocol, results

- Types: `Scope(tenant, session)`, `Record(id, scope, key, text, payload_sha256)`, `Ack`, `Ref`, `NotSupported`.
- The `Adapter` protocol exactly as in the design. `capabilities()` drives N/A cells.
- Worker: each system under test runs in its own subprocess. Harness and worker talk JSON lines over stdin and stdout. A write is acked only when the harness has read the worker's reply.
- Every payload carries a harness-computed SHA-256. Readback checks it, so torn records are detected the same way for every system.
- Fault targets: `worker`, `server`, `both`. The harness kills a server by PID with `os.kill(pid, SIGKILL)`, never `docker kill`. On macOS, servers run as native binaries.
- In-flight writes that were never acked may be present or absent. Only acked writes missing, or torn records, are violations.
- Results: per-operation JSONL, per-suite tables with systems in alphabetical order, and a manifest (system versions, config rows, hardware, OS, harness commit).
- Tests: protocol round trip, ack semantics (a reply never read is not an ack), hash check catches a flipped byte.

## T3: control systems and simple adapters

- Control systems (in `memproof/controls/`), each isolating one cause:
  - `buffered`: acks, then buffers in user space and flushes every 100 ms. Must fail `process-kill`.
  - `sqlite-off`: SQLite WAL `synchronous=OFF`, ack after commit. Must pass `process-kill`.
  - `md-rmw-sleep`: markdown read-modify-write with a fixed 5 ms sleep inside the window. Must fail `concurrent-*`.
  - `sqlite-busy`: SQLite with a busy timeout. Must pass `concurrent-*`.
  - `delayed-index`: indexes after a fixed 100 ms async delay. With a 1 ms poll, measured `visibility_lag` must fall between 100 ms and 100 ms plus 1 ms plus the read p99.
  - `sqlite-visible`: SQLite, visible on commit. Must pass `recall-delay`.
- Adapters: `markdown` (flat file, `rg`-style substring search, rows `append` and `rewrite`), `sqlite` (WAL + FTS5, path column, rows `synchronous=NORMAL` and `synchronous=FULL`).
- Strongest native mapping. Emulated or unsupported operations are marked.
- Tests: each adapter passes a shared conformance test for the methods it claims.

## T4: the 5 suites and the control gate

- `recall-delay`: write, then poll each documented read path (id, metadata filter, recency, search). Poll 10 ms, timeout 60 s. Report `write_latency`, `visibility_lag`, `time_to_visible` per path. Timeouts and `dropped` are separate.
- `history-scale`: grow one session to 1K, 10K, 100K (`--extended` 1M). Every record is reachable by every read path the system supports. At each size: last 20 by recency, get by key, search for a known record. Bulk load untimed. p50 and p99 per op and size.
- `process-kill`: acked writes, SIGKILL of each fault target at a random point, restart, read everything. Report acked writes lost and torn records. Help text and results say this tests user-space buffering and recovery, not disk durability.
- `concurrent-append`: 2, 4, 8 processes append distinct records to one scope. Report acked missing, duplicates, torn.
- `concurrent-kv`: 2, 4, 8 processes write distinct keys, then overlapping keys. Distinct: none missing. Overlapping: final value equals one intact acked write. CAS support and history are capabilities, not pass or fail.
- Control gate: `memproof controls` runs each suite's must-fail and must-pass controls. A must-fail control must fail in at least 90% of trials. The rate is written to `results/controls/`. If a suite's controls do not discriminate, that suite refuses to publish cells.
- Trials: default 20 per control, `--quick` 5 for CI.
- Deterministic embedder: a seeded hash embedder in `memproof/embed.py`. Used by every vector system.

## T5: MCP reference memory server and Qdrant

- MCP reference memory server: pin an exact npm version. SkillSpector scan first (see Rules). The worker spawns it over stdio as a child. Fault targets: `worker` (Python) and `server` (node PID). Map its entity/observation model to `Record` with the strongest native mapping. Mark what is emulated.
- Qdrant: pinned release binary for linux-x86_64 and macOS aarch64, with SHA-256 in `scripts/qdrant.sha256`. Native process, own data dir per run. Rows `wait=false` and `wait=true`. The row note and the adapter docstring say `wait` controls when a write is applied and visible, not fsync, and cite the Qdrant doc line. Payload index on scope fields so filters are native.
- Conformance tests for both. Skip with a clear reason if node or the binary is missing.
