>
> For agents: B2 ships as three milestones. Each task group is one branch, TDD, one commit per task, two independent reviews (Claude Opus 5.5 and Gemini 4 Argon) before merge.

**Spec:** `docs/design/0001-benchmark.md`, as amended on this branch (systems, milestones, embedder, sandbox policy).

**Owner decisions (2026-10-19):**

## B2a: protocol, suites, controls. No new third-party code.

B2a ships as two branches. B2a-1 is T1 to T4: protocol, conformance kit, Node worker, embedder, issue #1, adapter migration, and regenerated control evidence. B2a-2 is T5 to T7: gates, suites, controls and leak prevention. T7 must merge before any B2c branch.

### T1: protocol v1
- `docs/PROTOCOL.md` plus one JSON Schema file per op under `docs/protocol/v1/`. The schemas are documentation. The harness validates replies with hand-written stdlib checks that match them.
- Shapes:
  - Values carry an explicit `kind`: `record`, `ack`, `ref`. `scope` is a plain object `{tenant, session}`.
  - Unknown fields are ignored. Missing required fields fail.
  - `upsert` carries a full record, not an encoded string.
  - `error.type` is an enum: `not_supported`, `invalid_request`, `system_error`, `timeout`.
  - The harness computes every digest. Workers return text byte for byte.
  - `start` replies `protocol: 1`, `capabilities`, `version`, `notes`, and `servers: [{role, pid}]`. Fault targets are per role.
  - `ensure_server_exited` replaces `reap_server`. Any language can implement it.
  - Ops: `start`, `capabilities`, `write`, `bulk_load`, `read_recent`, `get`, `get_by_ref`, `list_prefix`, `search`, `upsert`, `delete`, `data_dirs`, `retrieve_for`, `stop`, `ensure_server_exited`.
  - `delete` takes a `ref`. A `ref` always means what that system's `write` returned. The harness never mixes record ids and refs.
  - Records may carry a harness-computed `vector`. Workers never embed on their own.
  - Stdout carries only protocol lines. Workers send logs to stderr.
- Every reply is validated. A malformed reply is a harness error for that cell, never a silently dropped ack.
- The worker command comes from `systems/<name>/manifest.json`.
- The current Python adapters move to this format.

### T2: conformance kit and a second-language worker
- Golden JSONL transcripts for every op, plus malformed-reply cases: missing `kind`, wrong ack id, non-UTF-8 output, stray stdout lines. An extra-fields case checks that unknown fields are ignored, not rejected.
- `memtorture conformance --command "<argv>"` replays them against any worker.
- A reference worker in Node, standard library only. It must not import or copy harness code. It passes the kit.

### T3: language-neutral embedder
- Define the embedder in `PROTOCOL.md`: SHA-256 over a counter and the text, unpacked to floats, then normalized. Exact byte layout and test vectors included.
- Replace the CPython `random` embedder. Any language reproduces it from the test vectors.
- The new embedder changes search results, so regenerate all committed control evidence and gates in this branch.
- Update the `Adapter` snippet in the design so `upsert`, `get_by_ref` and `delete` match T1.

### T4: fix issue #1
- `concurrent-kv` counts duplicates by record id. Versions per key become a capability.

### T5: gate changes
- Gate files are keyed by platform: `results/controls/<os>-<arch>/gate.json`. A Linux run never invalidates a macOS gate.
- `write-throughput` and `recovery` are ungated measurement suites, like `history-scale`. They say so in results.
- `supersede-by-key` gets a control. An append-only store that returns the oldest value must fail. SQLite upsert must pass.

### T6: suites `write-throughput`, `recovery`, `supersede-by-key`, `forget`, `forget-residue`
- As in the design table, with its controls.
- `forget-residue` first checks that a plaintext canary written before the delete is visible in `data_dirs`. If the canary is not visible, the system stores data in a form the scan cannot read, and the row is "not measurable". This decides which systems count as compressed, without a separate control.
- `forget` is judged against each system's own documented promise. The row cites the doc line.

### T7: leak prevention
- Run output goes only under `results/runs/`, which is gitignored. Control evidence goes under `results/controls/<os>-<arch>/`. Other output paths are rejected.
- `ResultWriter` does not render multi-system tables while governance blocks publication. `memtorture report --local` renders them for the owner's eyes only, with a banner.
- `memtorture export-system --system <name>` writes one system's raw output for its upstream issue.
- CI runs controls and baseline systems only (markdown, SQLite).

## B2b: `power-loss`

- LazyFS is test tooling. It gets a SkillSpector scan and an `APPROVAL` file like a benchmarked system. Its source build on the disposable machine is the one named exception to "no source builds". Pin a commit. Build it only on a disposable Linux machine, which counts as its sandbox: GitHub Actions first, the Azure CPU VM (`zerodb-bench-rg`) as fallback. Deallocate after each run.
- Systems run as native processes in a subdirectory of the LazyFS mount, never Docker over FUSE.
- LazyFS stays mounted for the whole run, without FUSE `writeback_cache`. Never unmount between trials: unmounting flushes dirty pages and ends the LazyFS daemon, which loses its cache before it can be cleared.
- Order per trial:
  1. SIGKILL every system process.
  2. `sync`, so dirty kernel `mmap` pages reach LazyFS as unsynced writes.
  3. `lazyfs::clear-cache` through the fault FIFO, which drops every unsynced write.
  4. `echo 3 > /proc/sys/vm/drop_caches`, so restart reads cannot hit clean kernel cache.
  5. Restart.
- If `sync` makes LazyFS treat data as synced, the `pwrite`-without-`fsync` must-fail control passes. The suite then publishes nothing. The controls decide whether this sequence works.
- Controls from the design, including the `mmap` pair. If the `mmap` must-fail control passes, `mmap`-based systems are "not measurable", never a pass.

## B2c: systems

### T1: sandbox runner and the exception policy
- Policy, as approved by the owner:
  - Only upstream release artifacts: PyPI wheels with the hashes PyPI publishes, upstream GitHub release binaries with upstream checksums or signatures, or upstream container images pinned by digest.
  - SkillSpector still scans each artifact. The full report stays in `.tools/` (gitignored). The commit says only "scanned, details held until governance allows".
  - The owner approves each system. The approval is a committed file `systems/<name>/APPROVAL` with date and scope.
  - Runs are sandboxed: non-root, no external network, writes only inside the run's workdir.
- How each cell is sandboxed:
  - **One supervisor per cell.** A small stdlib supervisor starts inside the sandbox and spawns every process the cell needs: servers, the embedding endpoint and workers. They share one network namespace with only loopback. PIDs are not unshared, so the harness can still kill by PID.
  - **No relay in the timed path.** The harness creates each worker's stdin and stdout pipes itself. It sends spawn and restart requests to the supervisor over a Unix control socket and passes the pipe ends as file descriptors (`SCM_RIGHTS`). Workers read and write those pipes directly. Timing stays in the harness, with no extra hop. Container workers are never relayed through `docker attach`.
  - **Linux:** bubblewrap with `--unshare-net`, `--ro-bind / /`, `--bind <workdir>`, and private `/tmp` and `/dev/shm` as tmpfs. `TMPDIR` points into the workdir. Ubuntu 24.04 restricts unprivileged user namespaces through AppArmor. CI runs a documented `sudo` setup step for this, then drops to an unprivileged user.
  - **macOS:** a committed `sandbox-exec` profile. Network only to loopback on the cell's reserved ports, and Unix sockets inside the workdir. Writes only inside the workdir. `TMPDIR` points into the workdir.
  - **Containers:** `--user` non-root, `--read-only`, `--cap-drop ALL`, `--network none`. The worker joins the server's network namespace. Server PIDs are resolved on the host, Linux only.
  - **Self-test before every run:** an outbound connect to an external address and a write outside the workdir must both fail. If either succeeds, the run aborts.
- No package code runs outside the sandbox at install time:
  - Python: `--only-binary :all:` and a hash-locked lock for the whole dependency closure.
  - Node: `npm ci --ignore-scripts`.
  - The `APPROVAL` file covers the whole locked closure, not only the top package.
- Artifact source per platform is listed in `systems/<name>/manifest.json`. Postgres and pgvector on Linux come from the signed PGDG apt repository. Redis 8 on Linux comes from the signed `packages.redis.io` apt repository. Packages are fetched with `apt-get download`, checked against the signed index hashes, and unpacked with `dpkg-deb -x` into `.tools/envs/<system>/`. Never `apt install` or `dpkg -i`, because their maintainer scripts run as root outside the sandbox. Where a platform has no upstream binary, the row is "not run on this platform". No Homebrew or source-build fallback.
- Apply the policy to Qdrant first. Its existing binary gets a scan and an `APPROVAL` file.
- `memtorture prepare <system>` downloads, verifies, scans and installs into `.tools/envs/<system>/`. The harness never imports system packages.

### T2: shared embedding endpoint
- A stdlib OpenAI-compatible `/v1/embeddings` server inside the sandbox, serving the T3 embedder. Systems that embed internally point at it. No system reaches a hosted model.
- Telemetry off for every system that has it (for example PostHog in Mem0, Chroma and Letta).

## Pre-registered expectations

- Most compared systems will not pass a complete `--no-llm` scan. That is why the sandbox exception exists. It is not a pass.
- Mem0's default local store will be N/A on concurrency suites.
- The MCP memory server stays blocked unless the owner-approved LLM-assisted scan returns a complete `SAFE`.
