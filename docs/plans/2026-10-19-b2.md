# B2: generic plug-in protocol, more suites, more systems. Implementation plan

> For agents: implementers on branches per task group, TDD, one commit per task. Two independent reviews (Claude Opus 5.5 and Gemini 4 Argon) of this plan before code, and of each branch before merge.

**Spec:** `docs/design/0001-benchmark.md` (approved), "Process model", "Tier 1", the Controls table, "Systems", "Governance", and the B2 row in "Milestones". This plan adds three things the design implies but does not spell out: a written worker protocol, per-system isolated environments, and a wider system list.

**Owner decisions (2026-10-19):** agent memory first. Benchmark must be generic: any memory tool, any language. Keep dependencies minimal. No GPU spend. Inference-cost experiments wait for GPUs.

**Rules:**
- The harness keeps zero runtime dependencies. System SDKs never enter the harness environment.
- Every third-party package or binary is pinned by version and hash, and scanned with SkillSpector (`--no-llm`) before install. Only a complete `SAFE` installs. A blocked system is reported as blocked with the scan summary, never silently dropped. LLM-assisted scans need the owner's approval per package.
- No LLM calls in B2. Systems that need an LLM to store memory (Mem0 `infer=True`, Graphiti, Cognee `cognify`) stay in B4 with a pinned local model.
- Plain short sentences in docs. No em dashes. Commits `git commit -s` with the Copilot trailer.

## G1: the generic protocol

### T1: write the protocol down
- `docs/PROTOCOL.md`, version 1. JSON lines over stdin and stdout. Every op the harness sends today (`start`, `write`, `bulk_load`, `read_recent`, `get`, `get_by_id`, `list_prefix`, `search`, `upsert`, `delete`, `stop`, `reap_server`), argument and reply shapes, error shape, `NotSupported`, capabilities, `server_pid`, version reporting.
- The harness owns timing, hashing and acks. A worker never reports its own latency.
- A `protocol` field in the `start` reply. The harness rejects unknown major versions.

### T2: conformance kit
- `memtorture conformance --command "<argv>"` runs the shared conformance tests against any worker command, in any language.
- A minimal reference worker in a second language (Node, standard library only) passes it. This proves the protocol is not Python-shaped.
- Tests: the Python adapters and the Node reference worker pass. A worker that lies about an ack id fails.

### T3: isolated system environments
- `systems/<name>/` holds the pin for one system: `requirements.txt` with `--hash` lines for Python, `package-lock.json` for Node, or a binary URL with SHA-256. Plus the adapter worker entry point.
- `memtorture prepare <system>` downloads without running package code, verifies hashes, scans, and only then installs into `.tools/envs/<system>/` (`uv venv` with `--require-hashes`, or `npm ci --ignore-scripts`).
- The worker for that system runs with that environment's interpreter. The harness never imports system packages.
- Qdrant moves to this layout without behavior change.

## G2: suites from the design

### T4: fix issue #1 first
- `concurrent-kv` counts duplicates by record id. Versions per key are reported as a capability. Required before any history-keeping system.

### T5: `write-throughput`, `recovery`
- As in the design table, with controls where the design defines them. `recovery` reports time to ready and RSS after open at 100K and 1M (extended).

### T6: `supersede-by-key`, `forget`, `forget-residue`
- With the design's controls: FTS5 row left behind must fail `forget`; `secure_delete=OFF` without `VACUUM` must fail `forget-residue`; SQLite with `secure_delete=ON`, FTS5 `secure-delete`, `VACUUM` and `wal_checkpoint(TRUNCATE)` must pass.
- `forget` is judged against each system's own documented promise. Cite the doc line in the row note.

### T7: `power-loss` on Linux
- LazyFS on the Azure CPU VM (`zerodb-bench-rg`, deallocate after each run). Native processes under the LazyFS mount, never Docker over FUSE.
- Order: SIGKILL, then clear the LazyFS cache, then restart.
- Controls from the design, including the `mmap` pair. If the `mmap` must-fail control passes, `mmap`-based systems are "not measurable", never a pass.

## G3: systems (no LLM on the write path)

Each system: pin, scan, isolated env, adapter worker, row notes citing upstream docs, and the strongest native mapping. Order by how often developers reach for it:

| System | How it runs | Rows |
|---|---|---|
| Chroma (self-hosted server) | Native server process, REST from the worker | default |
| Mem0 OSS | Python library in its own env, `infer=False`, its default local vector store | default |
| LangGraph store | `SqliteStore` from `langgraph-checkpoint-sqlite` in its own env | default |
| Redis agent-memory-server | Server process plus a pinned Redis, REST, background extraction off | default, plus Redis `appendfsync always` if documented |
| Letta | Server process, archival memory over REST, local embedding | default |
| MCP memory server 2.0.0 | Stays gated until a complete `SAFE` scan | n/a |

Systems whose server needs Docker run natively where upstream ships a binary or package. If a system cannot run without Docker, it runs in Docker for `process-kill` and the row says so; it is excluded from `power-loss`.
